Vault.

One place for what Toolbox keeps: 🔑 Secrets (connections, servers, keys — encrypted at rest) and 📦 Vault Data (workspaces → tables, stored as Parquet — load files; run SQL on it in Duck Lab). Anything saved without a workspace goes to system. See vault/CLAUDE.md for the trust model.

Workspaces

Every table lives in a workspace and is named workspace.table. system is built in: it catches everything saved without choosing a workspace.

    Pick a workspace

    Tables are stored as Parquet in Toolbox's storage (fast to query). Add data with ⬆ Load files; run SQL on it in Duck Lab; DataFrame Studio, SQL Studio and DataDiff load from / save to here too.

    Copy tables from a database saved in the Vault (Postgres, SQL Server, Oracle — SSH tunnels work) into a workspace, e.g. to stage data for a migration. The database is only read.

    Pick a connection, then “Show tables”.

    Files in an AWS S3 bucket (or any S3-compatible storage). Credentials are kept encrypted in the Vault as an S3 location.

    Copy a table that is already in Vault Data into a new table — most useful with the column map below: keep only some columns, rename, change types, fill empty values, or hide sensitive data (a masked copy to share).

    A template remembers names, types, fill values and the kind of protection — never salts or seeds, so type those again when you use it.

      Add SSH server
      
    
      For the SSH & SFTP tool: browse files, upload and run commands. A private key is safer than a password. First you confirm the server's fingerprint, so your login is never sent to an impostor; after that the tool refuses any server that presents a different key.       Backup & restore
      
    
      The Docker volume this data lives on already survives an ordinary rebuild/restart — this is a REAL, portable copy you can keep somewhere else entirely (another disk, cloud storage, a different machine), for the one case that doesn't survive: an explicit volume deletion.
